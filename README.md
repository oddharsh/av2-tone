# av2-tone

AV2 still images, encoded and decoded fast on a Mac, and checked bit for bit
against AVM, the AV2 reference software. This code grew up inside
[aadhar.sh](https://aadhar.sh/garage/av2) and moved here to stand on its own.

AV2 is the successor to AV1. AVM 1.0.0 shipped in May 2026, and no browser
decodes it yet. libavif calls its AV2 support "only for testing", so every
number below describes the pinned AVM and can move when the pin does.

## What's here

| dir | what it does |
|---|---|
| `encoder/` | libavif with AVM 1.0.0 at a pinned commit, plus a tuned build: 12 encoder patches and AVM's AVX2 kernels on arm64 through [SIMDe](https://github.com/simd-everywhere/simde). [Results](encoder/README.md) |
| `fast-decode/` | a native AV2 decoder for this machine: AVM plus NEON GDF, GDF across cores, and deblocking behind reconstruction |
| `wasm/` | AVM's decoder as a standalone WebAssembly module with no Emscripten glue (1.76 MB, about 430 KB Brotli) |
| `metal/` | AV2's GDF loop filter on the Apple GPU |
| `fixture/` | a deterministic synthetic test frame, so nothing here depends on a photo |
| `demo/` | encodes your photo as AV1 and AV2 at the same byte count, races the encoders and decoders on it, and shows both on a local page. [Usage](demo/README.md) |
| `rust/` | `av2-tone`, a safe-Rust still-image decoder, and its harness against pristine AVM. It parses every symbol but produces no pixels yet. [Details](rust/README.md) |

## Build

You need macOS on Apple Silicon, `brew install cmake ninja pkgconf aom`, and
[Bun](https://bun.sh). `wasm/` also needs `brew install emscripten`.

```bash
encoder/build.sh --tuned
fast-decode/build.sh
bun fast-decode/check.ts <dir of AV2 .avif files>
metal/run.sh
wasm/build.sh
```

`encoder/build.sh`, `check.ts` and `metal/run.sh` each fail on any difference
from pristine AVM:

- `encoder/build.sh --tuned` fetches libavif and AVM and builds the pristine
  pair in `encoder/build/` and the tuned pair in `encoder/build/tuned/`. It
  fails unless the tuned encoder, every new option off, writes byte-identical
  files. The first run takes a few minutes.
- `fast-decode/build.sh` builds a pristine and a fast decoder, and `check.ts`
  fails on any byte of difference between them, at one thread and at every
  core.
- `metal/run.sh` encodes the fixture at 4 quantizers and requires the GPU's GDF
  to match AVM's on every pixel for all 36 filter table sets.

`wasm/build.sh` writes `wasm/build/av2dec.<sha8>.wasm`.

## The safe-Rust decoder

`rust/av2-tone` is the crate this repo is named for: an AV2 still-image
decoder with no dependencies beyond std. It has three rules.

- **No unsafe.** `#![forbid(unsafe_code)]` sits at the crate root and in the
  workspace lints.
- **Every bitstream read is bounds-checked and returns a `Result`.** Clippy
  refuses unchecked indexing, `unwrap`, `expect` and `panic!`.
- **A panic is a bug.** Malformed input ends in `Truncated`, `Invalid` or
  `Unsupported`. `cargo test` cuts 4 real stills at every length and flips
  every header bit and every 61st tile-data bit. A one-off run over all 57
  corpus stills (148,029 flips) found no panic.

Its scope is one intra key frame in a single-picture sequence, which is what
this repo's encoder writes for a still at speed 6. Anything else is refused as
`Unsupported` ([the list](rust/README.md#scope)).

Against pristine AVM 1.0.0:

| stage | how it's checked | status |
|---|---|---|
| headers (AVIF, OBUs, sequence, frame, tile grid) | every field on all 57 corpus stills, down to the header's length in bits | matches |
| entropy decoder and CDF adaptation | 300 random streams from AVM's encoder, 1.2 million operations | matches |
| default CDFs | generated by running AVM's own setup code: 171 fields, 17,513 values | checked in |
| tiles and their starting context | byte for byte on all 57 | matches |
| tile parse | AVM's own symbol trace on all 57: 5,614,124 symbols across 107 read sites | matches |
| reconstruction | pixels | not built yet |

Next: dequantization, the inverse transforms, intra prediction, then
deblocking, CDEF, CCSO, GDF and loop restoration.

## Results

Measured on an M3 Max with other work running, so read them as approximate.
The encoder results' method and tables are in
[encoder/README.md](encoder/README.md).

- **Encode speed (patch 0006):** a speed-3 encode of a 600px tile on one core
  went from 37.9 s (pristine with SIMDe) to 30.7 s. AVM cleared a 16 KB scratch buffer on every
  forward transform.
- **GDF on a 1600x2400 frame:** 211 ms in AVM's C on one core, 3.7 ms in NEON
  across all cores, about 0.8 ms on the GPU.
- **The tools speed 6 switches off (0007):** turning TCQ and the IST/CCTX
  search back on (`tool-unlock=6`) moves AV2 from a tie with aadhar.sh's
  shipped AVIF to +1.02 ssimulacra2 at matched bytes. AV2 then wins about 148
  of 162 tiles, up from 116, at about 3x the encode time.
- **Perceptual quantizer experiments (0008 to 0011):** tune=iq's quantizer
  balance, jpegli's masking field as an RD map or a segment map, and jpegli's
  quantization matrices. None holds up as a ssimulacra2 win: each ties, loses,
  or loses on held-out photos. They stay in the build, off by default.
- **QM OBU cost (0012, 0013):** one or two levels of custom quantization
  matrix cost 118 to 182 B, 0.5 to 0.8% of a median 600px photo, so a custom
  shape has to beat that. 0012 makes a sent matrix quantize as written.
- **An AVM bug:** in a superblock mixing segment qindexes, AVM quantized a
  block at one qindex and signalled another. Patch 0010 fixes it for
  seg-maps; qmseg was never affected.
- **Dropped:** `-mcpu=native` (no change) and more than 4 encoder threads per
  tile (no faster).
